# Plan H2: Home — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Home is a rail tool (Home · Search · Research · Library · Player; Settings at the bottom). Opening the app still resumes the last book; first run, a crash and a reboot land on Home instead of the Library, and a setting offers always-Home. Home shows a readiness strip (nine dots and the first signal; tap → Readiness), Continue (where you left off, from the rail's data), and feeds: rows of cards drawn once a day from one primitive, a Feed = scope × kind × query stored in Room (`home_feeds`), with Random, On this day and Search as the kinds. Adding a feed is data, not code. Spec: `docs/superpowers/specs/2026-10-21-home-readiness-onboarding-design.md` §5, §7–§10.

**Out of this plan:** onboarding (H3; Start → Home is a one-line change there), the Research digest kind (project 4), Slim and Park (S1), a Home widget, any network call, any change to the readiness model (its calibration is a later session), and the voice.

**Architecture (what changes):**
- **`:app` shell and launch:** `RailTool.HOME` first in the enum; `HomeRoute`; `railToolOf` and `onTool` know it. `StartScreen.Home` joins `Reader` and `Library`; `LaunchDecider` lands first run, crash, reboot and "no tab" on Home; a pulled pack still lands on the Library with its notice (that is where it is fixed). `LaunchPrefs` (SharedPreferences, like `AppearancePrefs`) holds *Open to: Where I left off / Home*; Settings gets the section; `LaunchFacts.openTo` carries it into the decision.
- **`:core:library`:** entities `HomeFeed` (`home_feeds`: id, scope, kind, query, ordinal, addedAt) and `HomeDraw` (`home_draws`: feedId, day, cardsJson); `HomeDao`; `HomeFeeds` interface with `RoomHomeFeeds`; migration 11 → 12 (creates two tables, alters nothing); schema `12.json`.
- **`:app` home:** `FeedScope` (parsed from the scope string), `FeedKind` (RANDOM, ON_THIS_DAY, SEARCH), `FeedDrawer` (draws a feed's cards for a day from open archives, the book index and the library search; seeded by the date and the feed id; pure apart from the archive reads), `DayPage` (the Wikipedia day article's events, births and deaths), `HomeViewModel` (strip from `ReadinessModel.report`, Continue from the rail's `RailUi`, feeds drawn once per day and cached in `home_draws`), `HomeScreen` (strip, Continue row, feed rows, Add feed sheet, long-press Remove), first-run defaults seeded into `home_feeds`.
- **`GrangerNavHost`:** `composable<HomeRoute>`; `StartScreen.Home` navigates to Home over the Library root with the first transition skipped, as a resume does for the reader.

**Tech Stack:** unchanged: Kotlin 2.4.21, Compose Material 3, Room 2.8.5 (one migration, 11 → 12), kotlinx.serialization for the cached cards, Jsoup 1.21.2 (already in the version catalog) for the day page, Robolectric 4.17, JUnit 4 + Truth. ## Decisions

1. **Home is pushed over the Library root, not the root itself.** The nav graph's start destination stays `LibraryRoute`; a Home start navigates to `HomeRoute` at once with the first transition skipped, exactly as a reader resume does. Back from Home goes to the Library, as Back from Search does. Making Home the root would change Back for every Library user and deepen the resume stack (Home → Library → reader).
2. **A pulled pack still lands on the Library.** `LaunchDecider` sends first run, crash, reboot and "no last tab" to `StartScreen.Home()`; the "last tab's pack is gone" case keeps `StartScreen.Library(MISSING_NOTICE)`, because the Library is where the user fixes it. *Open to: Home* overrides everything except that notice.
3. **Scopes are strings with a small grammar,** parsed by `FeedScope.parse`: `library` (everything), `pack:<zimName>` (a pack by its ZIM Name, so a snapshot update keeps the feed), `family:<family>` (the first installed pack of a catalog family; `wikipedia`, `wikiquote`; resolved by the cached catalog's `family`, or by the name prefix `<family>_` when the catalog doesn't know the pack), `collection:<collectionId>` (a shelf collection; its books for Random and Search), `music`, `audiobooks`. A feed whose scope resolves to nothing is **hidden**, not shown empty: the default Quotes feed sits dormant until a Wikiquote pack is installed.
4. **Defaults are rows, seeded once.** On Home's first build with an empty `home_feeds` and no `home.seeded` mark (SharedPreferences `"home"`), four rows are inserted: On this day `family:wikipedia`, Random `family:wikipedia`, Random `collection:granger-classics`, Random `family:wikiquote` ("Quotes"). The user can remove any of them; removing all leaves Home with the strip and Continue.
5. **Once a day means cached.** A feed's cards for a day are drawn once (seed = `epochDay xor feedId`) and stored in `home_draws` (feedId, day, JSON cards); a later open the same day reads the row. A new day, an edited feed or a card whose target is gone (pack removed) redraws. `randomPath()` is libzim's own random, so the seed governs which of several draws and hits are kept, not libzim's choice; stability through the day comes from the cache.
6. **Cards carry their target as data.** `Card(title, subtitle, target)` with `CardTarget` = `Article(packId, path)` / `Book(bookId, href, progression)` / `Album(albumKey)` / `Audiobook(id)` / `Search(query)`; opening one goes through the nav host's existing closures (`sessions.openTab` + `nav.showTab`, `AlbumRoute`, `AudiobookRoute`, `SearchRoute`). No new reader entry points.
7. **On this day** reads the day article (`resolvePath("October_21")`, with `October 21` and the `A/` prefix as fallbacks) and parses its Events, Births and Deaths sections with Jsoup (`<h2>` ids or heading text, then the `<li>`s until the next `<h2>`); the day's seed picks three of each as cards whose target is the day article itself (the reader can show the section via `ReaderRoute.fragment`). A pack without the article falls back to `search("October 21", 30)` and the seed picks five hits. The feed title is the date ("October 21").
8. **Search feeds rotate.** `search(query, 30)` (or `BookIndex.search` for a book collection, `LibrarySearch.fullText` for `library`); the seed rotates the start offset and takes five. The feed's title is the query over the scope's name ("stoicism · Granger Classics").
9. **Random**: a pack → `randomPath()` five times (distinct, titles from `read()`'s HTML `<title>`); a book collection → five random `BookChunk`s of its books (via `BookIndex`, a chunk gives `href` and `progression`) shown as "Chapter · Book"; music → five random albums; audiobooks → five random audiobooks. Titles come from the data at draw time and are stored in the card.
10. **Continue is the rail's data.** `HomeViewModel` takes the rail's `StateFlow<RailUi>` and shows `Tab` and `Play` entries (newest first, up to eight) as cards; no second query, no second cover loader. The strip is `ReadinessModel.report` over the same four flows the Readiness screen uses; the nine dots use the primary colour at three alphas (None 0.25, Basic 0.6, Comprehensive 1).
11. **Migration 11 → 12 only creates tables.** R1 and R3 are on v11 with no migration; this plan takes 12 and the peer sessions are told when Task 3 lands, so a later migration takes 13.
12. **No feature flag.** Home ships in every build; nothing in it is tier-gated.
