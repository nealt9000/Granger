## 3. Architecture

**A Kotlin Multiplatform core under a SwiftUI app.** One Gradle build serves both phones; nothing forks.

| Layer | Android today | Both phones after I1–I3 |
| --- | --- | --- |
| Text, research, vectors | `:core:text`, `:core:research`, `:core:vectors` (JVM) | Same modules, KMP (`commonMain` + `jvm`/`android` + `iosArm64`/`iosSimulatorArm64`), as proven in I0 §4 |
| Catalog | `:core:catalog` (BouncyCastle Ed25519) | `:core:catalog-api` (I1); the signature check is BouncyCastle on Android, CryptoKit injected by the app on iOS |
| Online sources | `:app/online`, `:app/topic` (OkHttp) | `:core:online` (I1): blocking over `HttpFetch`, the app's `OkHttpClient` on Android (same `NetworkGate`), `NSURLSession` on iOS; no Ktor |
| Library store | `:core:library` on Room | Room KMP, one schema and one migration chain for both phones (bundled SQLite with FTS4) |
| Download rules, Outfitting | `:core:downloads`, `:app/online/Outfitting` | Rules and model shared; transport native (WorkManager / URLSession) |
| ZIM | `:core:zim` (java-libkiwix) | A Kotlin `ZimArchive` interface in common code (`:core:zim-api`, I1); Android implements it with java-libkiwix, iOS in Swift over CoreKiwix.xcframework (Kotlin/Native can't call C++) |
| Screens | Compose in `:app` | SwiftUI in `ios/`; Android unchanged |
| Readers, player, downloads, system | WebView, Readium Kotlin, Media3, WorkManager | `WKWebView` + `WKURLSchemeHandler`, Readium Swift, AVFoundation + MPNowPlayingInfoCenter, URLSession background sessions |

**The sharing rule:** logic, rules and pure screen state (the Home feed engine, search grouping, Explore's rooms and lenses, keeping, Outfitting) live in Kotlin and are unit-tested once. Android's `ViewModel`s stay in `:app`; on iOS small `@Observable` models call the core. SwiftUI only draws.

**One framework for Swift:** a `:shared` module exports `GrangerCore.xcframework` with **SKIE**, so Swift sees enums, sealed classes, `async` functions and `AsyncSequence`.

## 4. The repo and the dev-friend build

- `ios/` holds the app: `Granger.xcodeproj` (generated by XcodeGen from `ios/project.yml`, and committed, so a friend needs only Xcode), `Sources/`, the fonts, the voice's support files.
- **Signing:** `ios/Local.xcconfig` (git-ignored) sets `DEVELOPMENT_TEAM` and a bundle-ID prefix; `ios/Local.xcconfig.example` shows the two lines. Builds with a free Apple ID (7-day profile) or a paid one. No entitlement in the first build needs a paid team.
- **GrangerCore:** by default Xcode fetches a prebuilt `GrangerCore.xcframework` as a Swift Package binary target from a GitHub release (`ios-core-<date>`, checksum pinned). A friend changing Kotlin flips one setting to build it locally (needs JDK 17 and Gradle). This keeps "clone, open, run" true.
- `ios/README.md`: the three steps, what to try, how to send feedback (an email or a GitHub issue).
- **Builder's call:** CI isn't set up for iOS in I1–I5; the release of `GrangerCore` is made on the Mac by a script, like the catalog releases.

## 5. Navigation and look

- **A tab bar** in place of Android's rail: **Home, Explore, Search, Library**. Open articles and books are pushed on the tab's own stack (swipe-back works); the mini player sits above the tab bar. Settings opens from Home's header, as on Android. *(Builder's call: the iPhone idiom over a copy of the rail.)*
- Field and Night colours as SwiftUI tokens from the same values as `:app/theme`; Spectral for titles; system font for body text and lists so Dynamic Type and VoiceOver behave.
- System controls where Android uses custom ones only to look like iOS anyway (sheets, menus, swipe actions).

## 7. Rules carried from Android

- **No telemetry**; feedback by email (F1). App Privacy: "Data not collected".
- **Adult flags** (AF) and the default-screen picture rules (EX P0) apply on the iPhone too; they live in the shared core where they're logic.
- **Wikimedia etiquette:** the same User-Agent and per-host limits as `WikimediaClient` (4 per host).
- **The catalog signature is checked on the phone** before anything from it is used, same key.

## 8. Risks

| Risk | Plan | Mitigation |
| --- | --- | --- |
| Room KMP with 10k lines, 15 migrations and raw FTS4 | I3 | Convert behind the existing DAO interfaces; migration tests on both targets; fall back to SQLDelight for iOS only if Room KMP blocks |
| `WKWebView` differences in the page scripts (selection, read-aloud marks, link taps) | I2, I5 | Port the scripts unchanged first and test each bridge call; Kiwix's iOS app is the reference for `WKURLSchemeHandler` |
| Background downloads die on force-quit | I4 | Resume by Range + ETag on next open; say so in the downloads card |
| App Store and third-party GPL code (libkiwix, libzim, Xapian, espeak-ng) | I6 | No question for dev friends (public source); ask Kiwix in writing before TestFlight to non-developers |
| A second UI kept in step with Android | all | The sharing rule (§3); iPhone builds track Android's online build, not every Android experiment |
| The shared Mac (other sessions' Gradle and voice work) | all | One Gradle or Kotlin/Native build at a time; `-Pkotlin.compiler.execution.strategy=in-process` |
